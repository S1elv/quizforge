# QuizForge Classroom 2.1

QuizForge Classroom — production-oriented сервис оценки знаний для преподавателя и учащихся. Преподаватель создаёт тесты в свободном конструкторе, собирает их из банка вопросов, публикует отдельные версии, получает результаты и проверяет открытые ответы. Учащийся проходит тест без аккаунта и может указать только ник/имя по желанию.

## Возможности

### Конструктор

- 10 типов заданий: один ответ, несколько ответов, верно/неверно, пропуск, соответствие, короткий текст, развёрнутый ответ, порядок, число, код.
- Переключение типа вопроса в редакторе.
- Дублирование, удаление и изменение порядка вопросов.
- Разное количество баллов для каждого задания.
- Свободное сочетание типов в одном тесте.
- Импорт вопросов из банка в текущий тест.
- Стабильные ID вариантов, пар и элементов порядка; перемешивание не ломает проверку.
- Валидация перед публикацией.

### Публикации и версии

Каждое сохранение создаёт новую версию теста. Опубликованная версия фиксируется отдельно от текущего черновика. Поэтому преподаватель может редактировать уже опубликованный тест, не меняя тест для учащихся, которые заходят по существующему коду. Новая версия становится публичной только после отдельной публикации.

Попытка учащегося навсегда привязана к конкретному снимку версии теста.

### Прохождение

- Без регистрации.
- Код вида `QF-XXXXXX` и прямая ссылка.
- Имя/ник необязателен, если преподаватель не сделал его обязательным.
- Таймер и автоматическое завершение по серверному времени.
- Восстановление незавершённой попытки на том же устройстве.
- Серверное автосохранение каждого ответа.
- Локальный draft в браузере.
- Очередь ответов при отсутствии сети.
- Повторная отправка очереди после восстановления соединения.
- Защищённый opaque-токен попытки: в базе хранится только его SHA-256 hash.
- Защита от устаревших сетевых запросов к одному ответу через client revision.

### Контроль технических прерываний

При включённом отслеживании фиксируются:

- потеря/восстановление сети;
- скрытие вкладки;
- возвращение вкладки;
- `pagehide`;
- тайм-аут heartbeat;
- ожидающая автоматическая отправка после сбоя связи.

Перед фиксацией результатов преподаватель видит сигналы и журнал попытки. Эти события не трактуются автоматически как списывание.

### Результаты

- Живое обновление результатов из PostgreSQL каждые 2,5 секунды.
- Отдельные статусы «в процессе», «завершено», «истекло».
- Средний процент и количество прошедших установленный порог.
- Технические сигналы по каждой попытке.
- Карточка попытки с ответами и журналом событий.
- Ручная проверка коротких, развёрнутых и кодовых ответов.
- Комментарий к ручной оценке.
- Отметка попытки как проверенной.
- CSV-экспорт с процентом и порогом.

### Дизайн и UX

- Адаптивный интерфейс для desktop, tablet и mobile.
- Мобильная навигация без горизонтального скролла.
- PWA-установка на поддерживаемых браузерах.
- Темы: системная, Graphite, Ocean, Aurora, Paper, High Contrast.
- Сохранение выбранной темы.
- Поддержка `prefers-reduced-motion`.
- Контрастная тема для доступности.

## Стек

- React 19 + TypeScript.
- Vite 8.
- React Router.
- Express 5.
- Neon PostgreSQL через `@neondatabase/serverless`.
- Helmet, CORS, rate limiting, Zod.
- Vercel Functions / Node.js 22.
- Docker Compose для локального PostgreSQL.

Vercel поддерживает Express-приложения как Functions, а актуальная документация Vercel также описывает WebSocket-поддержку Functions. В этом релизе источник истины для результатов — PostgreSQL, а клиент использует DB-backed live refresh, поэтому мониторинг не зависит от памяти одного serverless-экземпляра.

## Локальный запуск

Требуется Node.js 22+ и PostgreSQL.

```bash
cp .env.example .env
docker compose up -d postgres
npm install
npm run migrate
npm run dev
```

Откройте:

```text
http://localhost:5173/setup
```

Первоначальная настройка создаёт первого преподавателя. Нужный ключ задаётся через `SETUP_KEY`.

Для локальной базы:

```env
DATABASE_URL="postgresql://quizforge:quizforge_dev_password@localhost:5432/quizforge"
SETUP_KEY="длинный-случайный-ключ"
CRON_SECRET="другой-длинный-случайный-ключ"
APP_URL="http://localhost:5173"
NODE_ENV="development"
PORT=3001
```

## Vercel + Neon

Создайте PostgreSQL в Neon и используйте pooled connection string в `DATABASE_URL`.

Импортируйте репозиторий в Vercel. Настройки сборки уже находятся в `vercel.json`:

```text
Framework: Vite
Build: npm run build --workspace client
Output: client/dist
Runtime API: Node.js 22
```

Production environment variables:

```env
DATABASE_URL="postgresql://..."
SETUP_KEY="минимум-32-случайных-символа"
CRON_SECRET="минимум-20-случайных-символов"
APP_URL="https://your-domain.example"
NODE_ENV="production"
```

Необязательно:

```env
CORS_ORIGIN="https://extra-origin.example"
```

После первого deployment:

1. Откройте `/setup`.
2. Создайте первый аккаунт преподавателя.
3. В Vercel ротируйте или удалите `SETUP_KEY`.
4. Проверьте `/api/health`.
5. Создайте первый тест, сохраните и опубликуйте его.
6. Проверьте прохождение через `/join`.

Vercel Cron вызывает `/api/cron/cleanup` каждые пять минут. Маршрут принимает только запрос с `Authorization: Bearer <CRON_SECRET>` и автоматически закрывает истёкшие попытки с ограничением времени и удаляет просроченные сессии.

Neon рекомендует использовать pooled connection string для serverless-запросов, а SQL-over-HTTP подходит для одношаговых запросов и транзакционных операций через серверless driver.

## Производственная безопасность

- Сессия преподавателя — HttpOnly/SameSite cookie, в production также Secure.
- Пароли — `scrypt` с уникальной солью.
- Токены попыток и сессий в базе хранятся в hash-виде.
- Write-запросы в production проходят strict Origin validation.
- API отключает браузерное кэширование через `Cache-Control: no-store`.
- В production включён Helmet с CSP и HSTS-поведением.
- Rate limit на вход, первичную настройку, подключение к тесту, ответы и heartbeat.
- Результаты ученика защищены opaque-токеном попытки.
- Правильные ответы и критерии ручной проверки не отправляются ученику.
- Публикация и черновик разделены на уровне базы.
